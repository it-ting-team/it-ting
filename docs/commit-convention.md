# 커밋 메시지 규칙

## 형식

```text
<유형>: <설명>

<본문(선택)>
```

- 설명은 한국어로 50자 이내로 작성하고, 끝에 마침표를 찍지 않는다.
- 설명은 무엇을 했는지 드러나게 작성한다. (예: `추가`, `수정`, `삭제`)
- 본문이 필요하면 제목 아래 한 줄을 비우고, 변경한 이유를 중심으로 작성한다.

## 유형

| 유형 | 용도 |
|---|---|
| `feat` | 기능 추가 |
| `fix` | 버그 수정 |
| `refactor` | 동작 변경 없는 코드 구조 개선 |
| `test` | 테스트 추가, 수정 |
| `docs` | 문서 작업 |
| `chore` | 설정, 환경 구성, 빌드, CI |

## 커밋 단위

- 한 커밋에는 하나의 변경 목적만 담는다.
- 빌드나 테스트가 깨진 상태로 커밋하지 않는다.
- 비밀번호, API 키, 웹훅 URL 같은 비밀값을 커밋하지 않는다.

## 예시

```text
feat: 게시글 작성 API 추가
fix: 댓글 삭제 시 권한 검사 오류 수정
docs: 브랜치 전략 문서 추가
chore: 새 PR Discord 알림 워크플로 추가
```

티켓 번호와 영역(`fe`, `be`, `infra`, `common`)은 [브랜치 이름](branch-strategy.md)에서 구분하므로 커밋 메시지에는 쓰지 않는다.

## AI 공동 작성 표시

AI 도구가 작성에 참여한 커밋은 본문 맨 아래에 `Co-Authored-By`를 표기한다.

```text
docs: 커밋 메시지 규칙 문서 추가

Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
```
