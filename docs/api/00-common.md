# 공통 API

여러 영역이 함께 쓰는 목록(캠퍼스 · 층, 기수, 학기, 관심사, 자기소개 질문)과 프로필 팝업을 다룬다. 다른 문서가 함께 쓰는 값의 모양도 여기에 한 번만 적는다. 규칙은 [API 공통 규칙](../api-convention.md)을 따른다.

- 명세: [00 공통](../spec/00-common.md)
- DB 설계: [계정 · 프로필 · 관심사 · 질문](../db/account.md), [들판 · 땅굴](../db/burrow.md)

## 함께 쓰는 값

다른 문서는 "사용자 표시", "관심사 태그"라는 이름으로 이 모양을 가리킨다.

API가 주는 값이 모두 DB 칼럼인 것은 아니다. `isShared`, `isRare`, `isCurrent`처럼 저장된 값에서 만들어 내는 값은 DB에 두지 않고 서버가 응답을 만들 때 계산한다([DB 설계 원칙](../db/README.md)).

### 사용자 표시

사람을 보여 주는 모든 곳에 쓴다([00 공통](../spec/00-common.md) 4). 실명, 반, 이메일은 담지 않는다.

| 이름 | 타입 | 설명 |
|---|---|---|
| `id` | 숫자 | 계정의 id |
| `nickname` | 문자열 | 닉네임. 탈퇴한 사용자는 `null` |
| `profileImageUrl` | 문자열 | 프로필 사진의 주소. 사진을 올리지 않은 사람과 탈퇴한 사용자는 `null` |
| `mole` | 객체 | 두더지 아이템. 아래 표 |
| `campusName` | 문자열 | 캠퍼스 이름. 탈퇴한 사용자는 `null` |
| `generation` | 숫자 | 기수. 탈퇴한 사용자는 `null` |
| `floor` | 숫자 | 층. 탈퇴한 사용자는 `null` |
| `isWithdrawn` | 참/거짓 | 탈퇴한 사용자인지 |

`mole`의 값은 부위마다 고른 아이템의 코드다. 고르지 않은 부위와 탈퇴한 사용자는 `null`이다.

| 이름 | 타입 | 설명 |
|---|---|---|
| `head` | 문자열 | 머리 아이템 코드 |
| `face` | 문자열 | 얼굴 아이템 코드 |
| `neck` | 문자열 | 목 아이템 코드 |
| `hand` | 문자열 | 손 아이템 코드 |

```json
{
  "id": 31,
  "nickname": "두더지왕",
  "profileImageUrl": null,
  "mole": { "head": "CAP_RED", "face": null, "neck": "SCARF_GREEN", "hand": null },
  "campusName": "서울",
  "generation": 14,
  "floor": 2,
  "isWithdrawn": false
}
```

탈퇴한 사용자의 이름("탈퇴한 사용자")과 기본 두더지 그림은 프론트엔드가 `isWithdrawn`을 보고 정한다.

프로필 사진은 선택이다. 사진이 없는 사람은 두더지로만 보여 준다. 사진을 어느 화면에 보여 주는지는 명세의 [보류한 결정](../spec/open-issues.md)이다.

### 관심사 태그

사람의 관심사를 보여 주는 곳에 쓴다([00 공통](../spec/00-common.md) 5).

| 이름 | 타입 | 설명 |
|---|---|---|
| `id` | 숫자 | 세부 관심사의 id |
| `name` | 문자열 | 세부 관심사 이름 |
| `categoryId` | 숫자 | 속한 대분류의 id |
| `isShared` | 참/거짓 | 나와 겹치는 관심사인지. 내 관심사를 볼 때는 `false` |

한 사람의 관심사 목록은 그 사람이 고른 순서로 준다. 첫 번째가 대표 관심사다.

`isShared`는 보는 사람에 따라 달라지므로 저장하지 않는다. 요청한 사람의 `user_interest`와 보이는 사람의 `user_interest`를 비교해 계산한다.

## GET /api/v1/campuses

캠퍼스와 캠퍼스마다의 층 목록을 준다. 회원가입 3, 내 정보 수정, 캠퍼스-층 고르기, 새 학기 안내, 추천 친구 설정이 함께 쓴다.

- 로그인: 필요(가입 중에도)
- 명세: 00 공통 19

### 요청

없다.

### 응답 `data`

| 이름 | 타입 | 설명 |
|---|---|---|
| `items` | 목록 | 캠퍼스 목록. 아래 표 |

| 이름 | 타입 | 설명 |
|---|---|---|
| `id` | 숫자 | 캠퍼스의 id |
| `name` | 문자열 | 캠퍼스 이름 |
| `floors` | 목록 | 그 캠퍼스의 층 목록. 항목은 `id`(캠퍼스-층의 id), `floor`(층 번호) |

```json
"data": {
  "items": [
    { "id": 1, "name": "서울", "floors": [ { "id": 11, "floor": 1 }, { "id": 12, "floor": 2 } ] }
  ]
}
```

다른 API의 `campusFloorId`에는 `floors`의 `id`를 보낸다.

### 요청

|---|---|---|---|---|
| 경로 | `userId` | 숫자 | ✓ | 볼 사람의 계정 id |

### 응답 `data`

| 이름 | 타입 | 설명 |
|---|---|---|
| `user` | 객체 | [사용자 표시](#사용자-표시) |

### 에러

| 상태 | `code` | 때 |
|---|---|---|
| `404` | `USER_NOT_FOUND` | 없는 사람이거나, 탈퇴했거나, 가입을 마치지 않은 사람 |

## 명세에 없어 이 문서에서 정한 것

- **기수 목록**: 명세는 기수를 "목록에서 고른다"고만 적었다. 인증 코드를 보낼 수 있는 기수를 서버가 알아야 하므로 서버가 목록을 준다.
- **"많이 고르는 취향"과 "통하는 취향"**: 서버가 관심사마다 `isRare`로 구분해 준다. 명세가 숫자를 보여주지 않는다고 했으므로 고른 사람 수는 주지 않는다.
- **탈퇴한 사람의 프로필 팝업**: 명세는 눌러도 팝업이 열리지 않는다고 했다. 주소로 직접 불러도 `USER_NOT_FOUND`로 답한다.

## 구현 단계로 넘기는 것

- 캠퍼스 · 층 · 기수 목록의 실제 값(명세에서 임시 값이다)
- "통하는 취향"으로 묶는 기준(명세에서 고른 사람 5명 이하가 제안 상태다)
- 대분류, 세부 관심사, 질문을 주는 순서(DB 설계에 순서 칼럼이 없다)
